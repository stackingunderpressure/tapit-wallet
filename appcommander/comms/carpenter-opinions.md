The reasoning is that the two credential shapes — org-issued membership versus joiner-signed self-membership — are mutually exclusive by `credential_type` and consumers will routinely need to dispatch between them, so keeping them in one file means a single import surface and one place to read both shapes side-by-side. `buildSelfMembershipDraft` produces an unsigned credential-kind attestation with `credential_type: 'self_membership'` and four top-level leaves — `org_id`, `org_name`, `joined_at`, `requested_at` — all set in a single `new Date().toISOString()` call so the two timestamps stay byte-identical for an envelope built in one shot. Under the Option 2 substrate (unilateral self-claim) they remain equal for the envelope's life; under Option 1 the org's roster snapshot timestamps the acceptance separately and the joiner's `requested_at` preserves their intent regardless. `isSelfMembership` is the mutually-exclusive predicate to `isMembership`. `readSelfMembership` lifts the signed leaves into a `SelfMembershipView`. `receiveSelfMembership` is the Phase E2 acceptor placeholder — throws on non-self-membership shape so callers can route by envelope shape without relying on UI-side dispatch guarantees, then holds and anchors the envelope locally via the existing `holdAndAnchor` helper. ## Section 2: What you could do better

The structural lesson worth naming is that a dispatched session ending without commit is a real failure mode the harness can hit, and the recovery cost was non-trivial — I burned maybe a third of this session's context on verification, audit, and close-out completion. The Stop hook the prior carpenter added in 4b26238 catches the case where a session tries to END with uncommitted commits on the branch but ahead of main, but it does not catch the case where a session DIES with uncommitted work in the index. The former is observable from outside (HEAD vs origin/main), the latter is not — only the next session sees it, and only if they ground correctly. A future hardening pass could add a heartbeat-style guard that periodically commits WIP to a `wip/` branch so an ungraceful death leaves a trail rather than a working-tree orphan. Not load-bearing today, but the entropy is real if the dispatched-session failure rate is non-zero.

The three-manifest governance-direction notes sweep — `connections/manifest.ts`, `cosigning/manifest.ts`, `settings/manifest.ts` all gaining a one-sentence "governance is the substrate primitive; this feature consumes it" explanation — is now deferred FOUR letters in a row. ## Section 3: The bigger picture

Phase E2 closes the producer-side of the open-joining axis, and what's interesting about it is how little code was actually required. The discriminated-union substrate Phase E1 landed in `authRule.ts` does the heavy structural lifting — it encodes joiner-side policy alongside signer-side multisig rules in the same Merkle-tree-of-leaves shape, provable via the same `disclosureProof` primitive the wallet has used since Phase 4. Phase E2 is just five exports and one new envelope-route action because the substrate was already doing the work. That ratio is the signal — when adding a major user-visible axis takes 200 lines and zero new cryptography, you've stacked the right primitives.

The substrate-agnostic property of this cut is the part worth dwelling on. The operator has not yet picked between Option 1 (org publishes a signed roster of accepted members), Option 2 (verifier walks the org's auth tree directly to check the joiner's claim against the declared policy), and Option 3 (hybrid). The Phase E2 work was deliberately written to work cleanly under all three because the joiner-side builder produces the same envelope shape regardless, and the org-side acceptor is a placeholder that holds the envelope locally. Phase E3 is where the substrate choice actually constrains the code — under Option 1 it ships a roster-publish job and a pending-roster buffer; under Option 2 it skips most of the org-side work and pushes verification to the joiner-side verifier in Phase E4. By writing E2 substrate-agnostic, the carpenter gave the operator the maximum optionality on the substrate decision without leaving a half-finished branch waiting.

The lesson the wallet keeps teaching across the codebase is that the right primitive at the bottom is worth ten features at the top. The leaves theory — every attestation is a Merkle tree of signed leaves, every disclosure is a proof of selective leaves with the rest hidden, every authorization is a leaf the org self-declared — generalizes across credentials, organizations, agreements, and predictions. Phase 8 is showing it generalizes across signer-side and joiner-side roles too. The carpenter inheriting Phase E3 walks into a substrate that already handles the encoding, the signing, the disclosure-proof, the verifier-side cross-envelope binding, and the routing — and they just have to write the policy-evaluation predicates for six join-policy kinds, all of which compose linearly. That's what makes the wallet feel like it's getting easier to extend rather than harder, three phases into the multisig org build-out. The substrate compounds, and tonight the operator's joiner-side membership-acquisition axis just got its foundation.
