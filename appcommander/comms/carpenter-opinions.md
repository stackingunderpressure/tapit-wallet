Cut 2 was the Supabase Storage backing for media when cloud-sync is on, at commit `49dbb09`. A new SQL migration at `supabase/migrations/20260522000001_create_wallet_media_bucket.sql` creates the `wallet_media` bucket with four owner-scoped RLS policies — select, insert, update, delete — each matching `(storage.foldername(name))[1] = auth.uid()::text` so the first folder segment in every object path IS the owner's auth.uid and RLS makes cross-user reads structurally impossible. A new `remoteMediaStore.ts` uploads and downloads JSON-wrapped `{ blob, mime }` objects via the Supabase Storage SDK with `upsert=true` so the same hash idempotently overwrites. The existing `mediaStore.ts` got refactored into a local-plus-remote coordinator the same shape as `walletStore` — `put` takes a `cloudSync` flag, encrypts once with `tapit-attest`'s `encrypt()`, writes the EncryptedBlob to IndexedDB always, and pushes the same EncryptedBlob to Storage if the flag is on. Remote failures log and swallow so the caller never sees a "save failed" for a successful local save. `get` tries local IDB first; on miss falls back to `remoteMediaStore.get`; on remote-hit caches the EncryptedBlob into local IDB without re-encrypting under a possibly-different passphrase. That last detail matters: when a user restores on a new device with the same passphrase, the cached EncryptedBlob from Storage decrypts cleanly because it was encrypted with the same passphrase originally. `createJournalEntry` gained a `cloudSync` parameter, `JournalComposer` reads `prefs.cloudSync` from `useWallet` and threads it through — the existing Settings toggle (default ON) now also decides whether photos and documents get mirrored to Supabase. Same architectural guarantee as `wallet_blobs`: encryption happens client-side via `tapit-attest`'s `encrypt()` before any network call, the host stores ciphertext only, the bytes that hit the wire are opaque to Supabase.

Cut 3 was the Web Share API integration at commit `ba04481`, and this is the one that gives you AirDrop. A new `src/shared/lib/share.ts` wraps `navigator.share` with three pieces of discipline — feature detection via `canShare()` so UIs hide the Share button on browsers without the API, `AbortError` handling so user-cancellation returns `'cancelled'` rather than falling back to clipboard (closing the share sheet IS a deliberate action), and a clipboard fallback for real share failures so the operator always has a usable path. Wired the share into all four producer-side modals — `CosignRequestModal`, `CosignAsWitnessModal` on its signed-return step, `CustodyHandoffModal` on its signed step, and `ShareProofModal` on its generated step. Each now shows a primary "Share via AirDrop / Messages / …" button alongside the existing Copy button when `canShare()` is true; on browsers without `navigator.share` the Copy button becomes primary, same UI shape as before. On iOS Safari and the installed PWA, tapping Share surfaces the system share sheet including AirDrop, Messages, Mail, and any other app the user has installed — which is what you asked for to make family-device envelope handoff feel native.

Cut 4 was the QR loop at commit `701d39f`. Both sides shipped. Encode uses the `qrcode` npm package (about ten kilobytes gzipped tree-shaken) and renders SVG so it scales crisp on retina; low error correction so each QR holds the maximum payload (roughly twenty-five hundred bytes binary or four thousand alphanumeric, more than enough for a typical signed envelope). If the payload exceeds the largest single QR version's capacity, the encoder throws and `QrShow.tsx` surfaces a friendly "this entry is too large for a QR code; use Share or Copy instead" message so the operator falls back cleanly without a confusing error. Decode uses the native `window.BarcodeDetector` API — no decode library shipped, zero new dependency surface. `BarcodeDetector` is available on Chrome desktop and Android since 83, Edge, and Safari iOS 17 onward, which covers the iPhone family. Firefox doesn't implement it; the scan modal shows a "QR scanning isn't supported on this browser; use Paste or Share instead" message and the user has clipboard fallback from Cut 3. `QrScanModal` opens the device camera with `facingMode: 'environment'` (rear camera, what you want for scanning), runs a `requestAnimationFrame` detect loop against the live video stream, and stops all media tracks plus sets a cancellation flag on unmount so a slow detector can't keep running after the user closes the modal. Producer modals — the four from Cut 3 — got a "Show as QR code" toggle that reveals the SVG below their textarea. Receiver modals — `CosignAsWitnessModal` on its paste step, `AbsorbCosignModal`, and the `/verify` route's `VerifyProofScreen` — got a "Scan QR" button next to their action button that opens `QrScanModal` and fills the textarea with the decoded payload on a successful scan.
