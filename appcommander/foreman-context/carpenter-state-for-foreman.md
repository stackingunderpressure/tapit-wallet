## WHAT-TO-FLAG

The inline-verify URL byte cap is set to 1800 bytes in QuickShareModal.tsx, chosen empirically — iMessage previews and QR-code generators prefer shorter URLs but the real threshold varies per chat engine. May need tuning once the operator sees how share cards actually flow. The share card uses the existing fresh-aurora-bg background helper for visual continuity, but a screenshot-target context is fundamentally different from an in-app surface (the animation does nothing in a static screenshot, the gradient eats into the assertion-line gravity); a future polish pass could give the share card its own purpose-built background. The membership preset surface lists one tile per held credential — fine for one or two memberships, could grow long for operators with many; a "show top 3, see all" pattern would handle that gracefully. ShareProofModal's adhoc-preset path produces "Proof from this {kind}" as the share-card headline which reads less editorial than the catalog's deliberate labels; future cut could let the operator type a custom assertion. Architectural note: the inline verify URL pathway commits to a specific JSON+base64url encoding; a v2 marker prefix on ?p= would be cheap to add later if we ever switch to a more compact serialization like CBOR.
