# Tapit Wallet — build plan

> Generated by Frank (AppCommander) on 2026-05-18. The governing
> spec is AppCommander's `project-memory/TAPIT_WALLET_SPEC.md`.
> This plan is that spec's work order, phased for this repo.

## What Tapit Wallet is (and is not)

It IS a person's sovereign identity wallet: a standalone app that
generates and holds the user's keypair and is the Merkle holder
of their signed attestations. It is the only place keys live, and
the hub other apps connect to.

It is NOT a cryptocurrency wallet, not a chatbot, not a feature
embedded inside another app. It does not hold coins; it holds
identity and reputation — signed attestations.

## Prime Directive

Build the smallest useful version correctly. The user's keys
never leave the wallet unencrypted — that rule outranks
everything. Clarity beats cleverness. A wallet a non-technical
person cannot use is a wallet that does not exist.

## v1 launch scope — the finish line

v1 is launched when a non-technical user can: install the wallet,
create an identity (Phase 2), see what they hold, back it up and
restore it, and approve a signing request from one other app
(Phase 3) — guided by the wallet bot if they get stuck (Phase 4).
Layer 3 (the peer network) is explicitly NOT in v1.

## Layer 1 — already built

The `Wallet` core object — keypair, succession, the attestation
holder, sign-both-ways, encrypted backup, sync, peer recovery —
is built and tested. It lives in the `tapit-attest` library,
inherited from the chassis at `tapit-attest/`. This app is built
*around* that object; do not rebuild it.

## Phase 1 — app shell + auth (job-001)

- **Goal:** Vite + React + TypeScript + Tailwind project shell;
  Supabase email/password auth; an empty wallet home screen
  post-login. Wire `tapit-attest` as a `file:` dependency.
- **Builds on:** the skeleton + the chassis.
- **Proof:** `npm install`, `npm run dev`, log in, land on the
  wallet home; `import { Wallet } from 'tapit-attest'` resolves.
- **Gate:** typecheck / lint / test / build all green.
- **Effort:** ~1 session.

## Phase 2 — wallet-core: identity + holdings (Layer 4 first cut)

- **Goal:** create an identity (`Wallet.generate()`), see your
  public key / identity, see your attestation holdings, back up
  the wallet to an encrypted blob, and restore from one. Rotation
  via the succession chain.
- **Builds on:** Phase 1; the `Wallet` object from `tapit-attest`.
- **Proof:** a user creates a wallet, backs it up, clears storage,
  restores it, and their identity + holdings return intact.
- **Gate:** four gates green; the keys-never-leave rule audited.
- **Effort:** ~2-3 sessions.

## Phase 3 — Layer 2: the inter-app connection pathway

- **Goal:** the `SignRequest` / `SignGrant` / `HoldRequest`
  message shapes (defined in `tapit-attest`'s shared library so
  every app inherits them), the Nostr NIP-46 transport (decision
  D-06 — chosen, with the message shapes kept transport-agnostic;
  see TAPIT_WALLET_SPEC.md §6), and a legible
  approval screen — who is asking, what claim, what it commits
  the user to.
- **Builds on:** Phase 2.
- **Proof:** a second app sends a `SignRequest`; the user sees and
  approves it; the wallet returns a signed attestation; both the
  signer's and the subject's wallet end up holding a verified
  copy.
- **Gate:** four gates green; the approval screen reviewed for
  legibility, not treated as plumbing.
- **Effort:** ~2-3 sessions.

## Phase 4 — the wallet bot (Layer 4)

- **Goal:** a conversational guide built on the chassis bot
  runtime (`supabase/functions/_shared/botRuntime.ts` + the
  persona module) that walks a non-technical user through key
  creation, backup, approval, and recovery.
- **Builds on:** Phases 2-3.
- **Proof:** a non-technical tester creates, backs up, restores,
  and uses the wallet guided only by the bot.
- **Gate:** four gates green.
- **Effort:** ~2 sessions.

## Phase 5 — Layer 3: the Mycelium peer network (DEFERRED)

Wallet-to-wallet discovery, connection, and mutual verification.
This is the largest layer and it is NOT started until it has its
own spec of record — `MYCELIUM_NETWORK_SPEC.md` — written first,
the same discipline that produced `ATTESTATION_PRIMITIVE_SPEC.md`.

## Total honest estimate

Phases 1-4: roughly 7-10 focused sessions to a launchable v1.
Phase 5 is a separate project with its own spec.

## Do NOT

- Do NOT re-implement anything in `tapit-attest` — inherit it.
- Do NOT put a private key anywhere but the user's wallet,
  encrypted. Not an env var, not a log, not a commit.
- Do NOT build Layer 3 before `MYCELIUM_NETWORK_SPEC.md` exists.
- Do NOT treat the approval screen as plumbing — it is the
  product.
- Do NOT add features beyond the five staged manifests without a
  decision logged in `decisions.md`.

## Recommended first move

Run `appcommander/jobs/job-001.md` — the app shell + auth + empty
wallet home. It is the smallest useful step and it proves the
`tapit-attest` `file:` dependency resolves.
